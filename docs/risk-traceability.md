## 3. Executive "Before vs. After" table (ready for Slide 5)

| Security dimension | BEFORE (MaisPlace legacy environment) | AFTER (AWS environment — Group G3) | Business impact |
| :--- | :--- | :--- | :--- |
| **Perimeter and Web Application** | Single server exposed directly to the Internet, no WAF and no protection against SQLi/brute force. | **Cloudflare Proxy + WAF (5 rules)** + **automated Fail2ban** + hidden origin (direct access to the IP blocked). | Continuous protection of revenue against web attacks and DDoS during campaigns. |
| **Data Isolation (LGPD)** | Application and database on the same flat network with few communication restrictions. | **MySQL in a private subnet** with no public IP, port `3306` exclusive to the `web-01` SG and TLS Full Strict. | Drastic reduction in the chance of customer database exfiltration and ANPD fines. |
| **Administrative Access** | Shared accounts with no single standard for remote access and no MFA (cause of Incident 2). | **Public SSH eliminated**; access via **Jump Server (Guacamole) with mandatory TOTP** + allowlist + 5 named IAM accounts. | Elimination of SSH brute-force attacks and individual traceability of actions. |
| **Visibility and Logs** | Scattered logs consulted only after failures; monitoring limited to "is it up or not". | **Wazuh SIEM (3 agents 4.9.2)** + **Zabbix 7.0 (4 hosts + e-mail)** + **CloudWatch/SNS** + **multi-region CloudTrail**. | Fast root-cause detection (proven in the real `db-01` incident) and forensic audit capability. |
| **Continuity and Backups** | Backups generated with no recent restore test. | **Daily AWS DLM (7 days)** + **daily MySQL dump** with a **validated real restore test** (51 tables checked). | Proven guarantee of recovering the e-commerce store in case of a serious failure or ransomware. |

## 4. Ready answers to the 7 mandatory presentation questions (Section 14)

Use this script to close the slides and prepare the team for the professor's questions:

1. **Which architecture was implemented?**  
   Dedicated VPC on AWS (`us-east-1`) segmented into a public subnet (`web-01`, `jump-01`, `g3-wazuh-server`) and a private subnet (`db-01` with no public IP), protected at the edge by **Cloudflare DNS/Proxy/WAF** and managed with **Security Groups referenced by role**, **CloudTrail**, **CloudWatch/SNS**, **Wazuh 4.9.2** and **Zabbix 7.0**.
2. **Which risks influenced the main architectural decisions?**  
   MaisPlace's 3 real incidents (downtime during a campaign, untraced administrative access in the middle of the night and a direct change in production) and the 8 Extreme risks in the matrix — especially data leaks (LGPD), intrusion through WooCommerce plugins, administrative brute force and the absence of logs.
3. **Which controls were implemented?**  
   Private database isolation, WAF with 5 rules, Fail2ban integrated with the Cloudflare API, Guacamole with TOTP + allowlist, named IAM + password policy + CloudTrail, Wazuh SIEM (FIM, SCA, Vulnerability Detection, 3 agents), Zabbix 7.0 (e-mail alerts), CloudWatch/SNS and automated backups (DLM + tested MySQL dump).
4. **How were these controls configured?**  
   Network least privilege: `web-01` accepts `80/443` only from the Cloudflare Prefix List and SSH only from the Guacamole SG; `db-01` accepts `3306` only from the `web-01` SG; `g3-wazuh-server` accepts agents only from the internal SGs and HTTPS dashboards only from authorized `/32` addresses.
5. **What evidence shows that they work?**  
   Dated screenshots of all SGs, IAM/CloudTrail, timeout on direct access to the web IP, WAF and Fail2ban blocks, 3 active agents in Wazuh, 4 green hosts and e-mail alerts in Zabbix, a real database restore test (Nov 17), the analysis of the real `db-01` incident (Zabbix detected the effect, Wazuh the cause) and the final external scan of Nov 19 (OWASP ZAP Baseline, after the fixes: no high alerts, 7 medium). *Limit:* the scan is passive and does not cover authenticated routes or the origin server.
6. **Which risks remain (residual risks)?**  
   * **Lab technical risks:** no MFA on AWS (risk accepted by the group in an academic environment), unencrypted EBS volumes, no AWS Secrets Manager (static keys on `wazuh-cloudwatch-reader` and a Cloudflare token without expiration), no Auto Scaling/Multi-AZ and tight memory on the Wazuh+Zabbix server.
   * **Organizational (proposed plan):** phishing awareness program, formal third-party management/offboarding, a formal incident response plan with a DPO (LGPD) and separate Dev/Staging/Prod environments.
7. **What would be implemented in a next production stage?**  
   Migration of the database to **Amazon RDS Multi-AZ encrypted with KMS**, **ALB + Auto Scaling** for campaigns, **AWS Secrets Manager** with automatic rotation + IAM Roles eliminating fixed keys, **mandatory MFA on AWS** (WordPress has had TOTP MFA since Nov 18), an immutable cross-region copy of backups in S3/Vault Lock, separate accounts via AWS Organizations + IaC (Terraform) and an Incident Response Plan with periodic exercises.
