# External scan

Scan of the store's public surface (`https://maisplace.net.br/`) with OWASP ZAP, done twice: on 2026-11-18, as a baseline, and on 2026-11-19, after the fixes on the web server and the database.

## Method

- **Tool:** OWASP ZAP 2.17.0, image `ghcr.io/zaproxy/zaproxy:stable`, script `zap-baseline.py`.
- **Mode:** *Baseline*, that is, a short crawl (`-m 2`) and passive rules only. No attack is sent.
- **Scope:** only the public surface, unauthenticated, going through Cloudflare.
- **Output:** HTML, JSON and Markdown reports in a folder named with date and time.

## How to run

Requires Docker. From the repository root:

```bash
bash external-scan/rodar_scan_passivo.sh
```

The script only accepts `https://maisplace.net.br/` as the target and writes to `external-scan/scan_<date>_<time>/`. ZAP exits with code 2 when there are warnings (`WARN`); this does not mean the run failed.

## Result

| | Nov 18 | Nov 19 |
| --- | --- | --- |
| High alerts | 0 | 0 |
| Medium alerts | 8 | 7 |
| Low alerts | 10 | 10 |
| Informational alerts | 10 | 10 |
| Alert types | 28 | 27 |
| Instances | 109 | 108 |
| Endpoints in the report | 158 | 158 |
| URLs in the crawl | 235 | not recorded |

Between the two scans, WordPress moved to version 7.1.5, the security packages were applied on web-01 and db-01 and Apache started sending HSTS, `X-Frame-Options`, `X-Content-Type-Options` and `Referrer-Policy`. The clickjacking alert (5 instances) disappeared. Still open: missing CSP, automated anti-CSRF token warnings and the `moment.js` library bundled with WordPress.

## Limits

- Passive, unauthenticated scan: it does not cover authenticated routes, checkout or integrations.
- Traffic goes through Cloudflare, so the origin server is not tested directly. Part of the remaining alerts come from responses generated by Cloudflare itself or from cached files.
- "No high alerts" applies to what ZAP observed. It does not show the absence of high vulnerabilities.
- The complementary attempt with WPScan on Nov 18 was interrupted by request limits (429 and 403 responses) before enumerating plugins; the `wpscan_limites.json` file records the incomplete coverage, not a result.
